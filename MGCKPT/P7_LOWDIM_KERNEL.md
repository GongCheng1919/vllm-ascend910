## ★ 一句话给接手的人

**P6.5 交付的那张表上，我们的 W4A8 在 TP=4 只剩 1.16× BF16（batch=1），
batch≥128 还输给我们自己的 W8A8。而 PP=4 上同一个模型是 2.0–2.2×。**
P7 要回答的是：**这个塌陷里有多少是我们的算子在低维度分片下自己变慢了。**

「低维度」指的是 TP 把每个 rank 的 GEMM 切小之后的形状。QwQ-32B 在 TP=4 上：

| 层 | 切法 | TP=1 | TP=4 每 rank |
|---|---|---|---|
| qkv_proj | 列并行（切 N）| N=7680 | N=1920 |
| o_proj | 行并行（切 K）| K=5120 | **K=1280** |
| gate_up_proj | 列并行（切 N）| N=55296 | N=13824 |
| down_proj | 行并行（切 K）| K=27648 | **K=6912** |

已知的靶子：**行并行 eff@4 = 0.54**（P6.5 §5，ragged-K 之后从 0.25 提上来的，
但离 1.0 还差一半），而列并行 eff@4 是 0.77–1.06（P6 §1.3，几乎完美）。
⇒ **问题在切 K 的那两层，不在切 N 的那两层。**

**⚠ 但 P7 的规模还没定，第一步就是去定它**（见 §2 第 0/1 项）。如果 P6.5 那
31 ms/step 里有 14 ms 是不重叠的通信，那 P7 的天花板就只有剩下的 17 ms；
反过来如果通信只占一小部分，P7 就是主战场而 P8 不值得开。
**这两种可能指向完全相反的后续，而且不能靠外推分辨**（P6.5 D1 就是被逐层外推
坑过一次）。

### D2（2026-08-19）收益域：W4A8-mg 赢在「小 M × 大 K」，两端各有一个独立机制

对 `int4_cube_lab/results/p65_ragged_tp.csv` 的 o_proj 行（N=5120 固定，
只扫 K ∈ {640, 1280, 2560, 5120}），把耗时拟成 `固定开销 + K·斜率`：

| M | W4A8 固定 | W4A8 斜率 | W8A8 固定 | W8A8 斜率 | **斜率比** | 固定差 | **交叉点 K\*** |
|--:|--:|--:|--:|--:|--:|--:|--:|
| 16 | 15.4 µs | 2.24 µs/kK | 12.8 µs | 3.75 µs/kK | **0.60** | +2.5 µs | **1665** |
| 128 | 23.9 µs | 3.12 | 13.0 | 5.89 | **0.53** | +10.8 | **3912** |
| 512 | 36.2 µs | 13.90 | 19.5 | 13.85 | **1.00** | +16.8 | 全输 |

三条结论：

1. **访存优势完好无损。** 斜率比 M=16 是 0.60、M=128 是 0.53，理论值 0.5。
   「小 M 下 W4A8 的带宽优势很快消失」是**错觉**——消失的不是斜率。
2. **消失的是固定开销。** +2.5 / +10.8 / +16.8 µs，随 M 单调涨（= P5 的分组
   冲刷税，按冲刷次数/行数收费）。K 越小它占比越大，`K* = 固定差 / 斜率差`，
   M=16 时 **K\* = 1665**。实测对照（`new_vs_w8`，<1 = 我们赢）：
   `o_proj@TP=4` K=1280 → **1.066 输**；K=2560 → 0.935 赢；
   `down_proj@TP=1` K=27648 → **0.615，赢 1.63×**。
3. **M=512 斜率比 = 1.00，访存优势结构性归零。** 这不是实现问题，是算术：
   MSD 把 A 拆成两个 int4 平面 = **两遍 Mmad**，而 int4 cube 是 int8 的 **2×**，
   `2 遍 × 2× 速度 = 与一遍 int8 完全相等`。⇒ **compute-bound 区，W4A8-MSD
   相对 W8A8 的计算优势恒为零**，再叠上固定开销必输。

**这把「PP 行 TP 不行」从现象变成了机理**：PP 不切 K（o=5120 / down=27648，
两层都在收益域内 ⇒ 2.0–2.2×）；TP=4 把 `o_proj` 切到 K=1280 < K\*，跌出收益域。
§1 里那条「行并行 eff@4 = 0.54」就是这一条。

**与 §1「TP 的失败不在 kernel」不矛盾**：那条说的是 *W4A8 自己* 的 TP 扩展有效
（Computing 精确减半，账逐项对上）；D2 说的是 *W4A8 相对 W8A8 的优势* 在
K < K\* 时消失。两件不同的事，都成立。

> ⚠ **限定**：4 个点的单次拟合，重复性门禁（§2 第 0 项）尚未做。
> 0.60 / 0.53 / 1.00 这个梯度远超 ±15% 噪声带，**方向可信**；
> **具体数值在门禁之前不得写进任何对外指标。**

### P7 的靶子（由 D2 导出）

**把 M=16 的 K\* 从 1665 压到 1280 以下**，`o_proj@TP=4` 即回到收益域。
**只打固定项，不碰斜率**——斜率已经是理论值，那里没有空间。

### CV 协作结构（D1 指向的地方）

一个 kernel 里同时有 AIC 和 AIV，靠 **GM workspace + 4 个 CrossCore flag
（2 个 slot 双缓冲）** 协作：

```
AIC  (行 550–892)   Mmad ─► Fixpipe(L0C ─► GM workspace) ─► SetFlag(kAicToAiv{0,1})
AIV  (行 893–1168)  WaitFlag ─► 从 workspace 读 int32 partial
                    ─► 每组 dequant + fp32 累加(UB) ─► SetFlag(kAivToAic{0,1}) 归还 slot
```

⇒ **每个量化组的部分和都要走一趟 `L0C → GM → UB`，外加两次 CrossCore 握手。**
K=1280 时只有 2 个组，这趟往返摊不开；K=27648 有 27 个组，就摊开了。
**这是 D2 那笔固定开销的最大嫌疑人**，也是 D1 所说的结构性问题。

| 行 | 内容 |
|---|---|
| 141–306 | 编译期几何：`TILE_M / TILE_N=128 / GK / INNER_K / kL0CDepth / UB 预算 / BATCH_G` |
| 261–265 | CrossCore flag 编号与 `kCrossMode` |
| 403–431 | `IssueGroupLoad` — GM→L1 的整组装载 |
| 433–488 | `AccumulateGroupChunk` — AIV 侧每组的 dequant + fp32 累加（含 asym 的 rank-1 折叠） |
| 599–620 | `FixpipeParamsV220` — L0C→GM 的下发参数 |
| 622–892 | `MmadParams` + AIC 主循环；**754–764 与 836–862 是冲刷点/握手点** |

### 已接好的消融开关（改 `.cpp` 的 `#define`，不用动 `.inc`）

| 开关 | 作用 |
|---|---|
| `ABLATE_AIV_CFG=1` | AIV 只握手不干活 ⇒ 分辨「AIC 等 AIV」还是「AIC 自己慢」。输出是垃圾，只用于计时 |
| `ABLATE_AIC_CFG=1 / 2` | 1 = 去掉 Fixpipe；2 = 只留 GM→L1 DMA（本访问模式的权重流地板） |
| `SPLIT_MSD_FLUSH_CFG=1 / 2` | 把堆叠的 MSD 冲刷拆成两个半高 L0C tile，恢复双缓冲（P5 D6） |
| `BF16_FLUSH_CFG=1` | 冲刷时 int32→bf16，workspace 字节双向减半。**非逐位一致，禁止设默认** |
| `BAND_N_CFG=1` | L2 分带遍历，逐位一致，prefill +2.3–4.8%（待设默认） |
