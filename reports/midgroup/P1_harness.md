## 1. 一句话结论（交给 P2）

**RTN 对称出局；但加上权重零点后，缺口只剩 1.6 个百分点，方案仍然活着。**
完整 WikiText-2 test split 上，`W4A8-mg1024` 相对 W8A8 退化 **+9.03%**（对称 RTN）
→ **+3.56%**（非对称 RTN）。门槛是 ≤2%，**只差 1.56 个百分点**。

**GK 不是那个杠杆，逐通道缩放（AWQ）也不是。** GK 从 1024 缩到 128（组数 8 倍，
按 P0 的代价表根本买不起）只赚回约 1/3 的缺口；AWQ 式逐通道缩放两个方向都只值
0.3–0.5 dB（§4b）。Tier1 指出机理：**mid-group 与逐通道缩放都作用在不是瓶颈的那一侧，
int4 权重的难度是行内/组内的无结构散布。**

**而无结构散布正是 GPTQ 的适用条件。** 所以 P2 的路线很明确：
**非对称权重（已到手 5.5 个百分点）+ GPTQ（需要补上最后 1.6 个）**，
跳过 RTN 对称、不花机时细化 GK；AWQ 不做主力，但缺口只剩 1.6 个百分点后它的
0.3–0.5 dB 已不可忽略，留作 GPTQ 之后的补齐手段。

## 2. Harness 定义（与路线图 §5 严格一致）

- **W**：int4 对称，per-(output channel, K-group)，scale = `max|w|/7`。
- **A**：int8 对称，per-(token, K-group)，**动态**，scale = `max|a|/127`。
- **scale 一律 bf16**，且**先 round 到 bf16 再用它量化**——kernel 里就是 bf16，
  用 fp32 scale 做 fake quant 会系统性高估精度。这一条由自检 T1 守住。
- 作用域：仅 Linear（qkv / o / gate / up / down）。embedding、lm_head、norm、
  attention 内部的 QK/PV 不动。
- **不建模 MSD 拆分**：`a = 16h + l + 8` 在 int32 内精确（`REPORT_W4A8.md` §1），
  对数值零影响。拆分函数仍实现了，供 P3 对拍字节，由自检 T3 覆盖全部 256 个 int8 值。

### GEMM 与 kernel 数学等价，不是近似

```
每个 K-group g:  partial = A_q[:, g] @ W_q[:, g].T      整数精确
                 acc    += partial * as[:, g] * ws[:, g]   fp32
y = acc.to(bf16)
```

`partial` 用 **fp32 matmul** 算：算子是小整数（|A_q| ≤ 127、|W_q| ≤ 8，在 fp32 与
cube 的 hf32 输入格式里都精确），`|partial| ≤ GK·127·8 ≈ 1e6 < 2^24`，所以 fp32
累加器精确，等于 cube 的 int32 累加。**这一点没有假设，自检 T4 用 CPU int64 参考
逐 shape 验过**（5 组 shape，最大相对误差 8e-8，只是 fp32 rescale 的余量）。

实测 fp32 matmul 在 910B4 上只比 bf16 慢 3.5×（2048×5120×5120：1.63 vs 0.46 ms），
所以保真路径是负担得起的，不需要退而求其次。另有一条 `--mode fast`（反量化成
bf16 后单次 bf16 matmul）快路径，自检 T6 量出它比精确路径低约 27 dB——够干净，
但正文所有数字都用 `exact`。

### 五组对照（同一 harness、同一评测集、一次权重扫描）

| 组 | W | A |
|---|---|---|
| `bf16` | — | — |
| `w8a8` | int8 per-channel | int8 per-token |
| `w8a8-mg{GK}` | int8 mid-group | int8 mid-group |
| **`w4a8-mg{GK}`** | **int4 mid-group** | **int8 mid-group** |

`w8a8-mg` 用来把「mid-group 本身的影响」与「W 降到 4bit 的影响」拆开——事实证明
这一组是本轮最关键的对照（§3.3）。

## 3. 结果

### 3.1 Exit Criteria 核对

- [x] **BF16 组与原模型逐位一致**：streaming 引擎的 logits 与
      `Qwen2ForCausalLM.forward` `max|diff| = 0.000e+00`（`run_selftest_model.py` M1）。
      NLL 差 1.2e-6，纯粹是 loss 归约的求和顺序不同（logits 已逐位相同）。
- [x] **五组配置可在同一份权重上产出**：见下表。
- [x] **单 GEMM 级 SNR 可导出**：`results/tier12_gk1024.csv`，64 层 × 7 个 Linear
      × 4 组配置 = 1792 行。

### 3.2 WikiText-2 PPL（**完整 test split**，150 窗口 / 307k token，GK=1024）

`results/ppl_gk1024_full.json`。五组配置 + 非对称，同一次权重扫描，`mode=exact`。

| 配置 | PPL | ΔPPL vs bf16 | **ΔPPL vs w8a8** | KL(bf16‖·) nats |
|---|---:|---:|---:|---:|
| `bf16` | 6.6605 | — | −0.17% | — |
| `w8a8` | 6.6716 | +0.17% | 0 | 0.0643 |
| `w8a8-mg1024` | 6.6651 | +0.07% | **−0.10%** | **0.0182** |
| `w4a8-mg1024` | 7.2739 | +9.21% | **+9.03%** | 0.2416 |
| `w4a8-mg1024-asym`（非冻结） | 6.9092 | +3.73% | **+3.56%** | 0.1802 |
| `w4a8-pc` | 8.9297 | +34.07% | +33.85% | 0.4927 |

三点：

1. **W8A8 无损**（+0.17% vs BF16），harness 本身可信。
2. **`w8a8-mg1024` 比 per-token W8A8 还略好**（−0.10%，KL 0.018 vs 0.064）——
   mid-group 在激活侧是净收益，独立佐证了 nitro 侧已验证的 A8 g1024。
3. **`w4a8-pc` +33.9%**：per-channel W4A8（即 `int4_cube_lab` 已实现的那版 kernel
   对应的算法配置）**不是一个可用的回退点**。

### 3.2b ⚠️ 小样本会**系统性高估**退化，不只是噪声

本轮先用 8 窗口（16k token）跑过一遍，两组数字差了近一倍：

| 配置 | 8 窗口 | **完整 150 窗口** |
|---|---:|---:|
| `w8a8-mg1024` | +0.34% | −0.10% |
| `w4a8-mg1024` | +18.67% | **+9.03%** |
| `w4a8-mg1024-asym` | +11.02% | **+3.56%** |
| `w4a8-pc` | +52.75% | +33.85% |

原因不是随机噪声：前 8 个窗口的 BF16 PPL 是 **4.89**，全集是 **6.66**——开头那段文本
明显更容易，模型在上面更自信，量化噪声的相对伤害就更大。**这是偏差不是方差，换种子
救不回来。** P2 的任何门禁数字都必须在完整 split 上取。

### 3.3 Tier1 / Tier2：为什么 GK 救不了

`results/tier12_gk1024.csv`，64 层中位数，dB：

| 配置 | 指标 | q_proj | o_proj | gate_proj | down_proj |
|---|---|---:|---:|---:|---:|
| `w8a8` | T1 激活 | 26.88 | 32.83 | 33.80 | **21.23** |
| `w8a8-mg1024` | T1 激活 | 30.31 | 36.07 | 36.74 | **29.74** |
| `w8a8` | T1 权重 | 39.65 | 39.71 | 40.09 | 38.41 |
| `w8a8-mg1024` | T1 权重 | 41.09 | 41.40 | 41.43 | 41.31 |
| `w4a8-pc` | T1 权重 | 14.48 | 14.56 | 14.96 | 13.48 |
| `w4a8-mg1024` | T1 权重 | **15.92** | 16.22 | 16.26 | 16.18 |
| `w8a8` | T2 GEMM | 29.32 | 32.66 | 36.49 | 22.10 |
| `w8a8-mg1024` | T2 GEMM | 32.74 | 35.79 | 39.07 | 30.58 |
| `w4a8-mg1024` | T2 GEMM | 18.94 | 17.16 | 19.46 | 17.21 |

读法：

1. **mid-group 对激活很值钱**：per-token → GK=1024 在 `down_proj` 上是
   **21.2 → 29.7 dB（+8.5 dB）**，其他投影 +3～3.4 dB。原因是
   `down_proj` 的输入（SwiGLU 乘积）离群极重，实测**逐行 crest factor 中位数 126**，
   per-token 一个 scale 罩不住，分组把离群点关进了一个组里。
2. **mid-group 对权重几乎不值钱**：int4 权重 per-channel → GK=1024 只有
   **+1.3～2.7 dB**；一路缩到 GK=128 也只到 18.3 dB（独立对拍见 §5）。
3. **所以 W4A8 的 T2 被 int4 权重噪声钉死在 17–19 dB**，激活侧那 +8.5 dB 完全看不见。
   作为对照，它要替换掉的 W8A8-pc 路径是 22–33 dB——**W4A8 比它多约 10 dB 的 GEMM 噪声**。

**这解释了 §3.2 的曲线：GK 只作用在已经不是瓶颈的那一侧。**

### 3.4 继承自 INT8 研究的判据不能直接搬过来

路线图 §9 的风险项「`snr_midgroup_sweep.py` 的 INT8 判据未必适用于 W4」——**证实了，
而且比预想的更严重：连 `w8a8` 自己都过不了**（T1 激活最差 14.53 dB < 32 dB，
T2 最差 9.40 dB < 35 dB），可它的 PPL 是无损的。

| 配置 | T1-X 最差 | T1-W 最差 | T2 最差 | 32/35 dB 判定 | 实际 ΔPPL vs w8a8（全集） |
|---|---:|---:|---:|---|---:|
| `w8a8` | 14.53 | 28.25 | 9.40 | FAIL | **0（相对 BF16 +0.17%，无损）** |
| `w8a8-mg1024` | 25.36 | 31.66 | 14.57 | FAIL | **−0.10%** |
| `w4a8-mg1024` | 25.36 | 10.74 | 12.30 | FAIL | +9.03% |
| `w4a8-pc` | 14.53 | 8.81 | 8.86 | FAIL | +33.85% |

原判据来自 NPU-OP 的**预训练模型 + INT8**场景，那里激活分布是训练时受控的。现成的
QwQ-32B 不是那个分布。**P2 不要用绝对 dB 做门禁**，用 PPL / 任务评测，以 W8A8 为参照系；
Tier1/2 保留为**定位问题层**的诊断工具（它在这个用途上很好用——直接指出了 §3.3 的归因）。

顺带：`logit SNR` 也是个坏判据。`w8a8` 的 logit SNR 只有 13.3 dB 却 PPL 无损——
误差主要是 softmax 会抵消的共模分量。因此 runner 现在额外输出
**KL(bf16 ‖ config)**，这才是 P2 该看的保真度标量。

## 4. 最有价值的杠杆：权重零点（非对称 int4）

既然瓶颈在权重侧，而缩 GK 对权重只值 1.5 dB，本轮量了**非对称 int4**（每组一个零点）。
**这是 P1 找到的最有价值的一件事**——它一步把缺口从 9.03 砍到 3.56 个百分点：

| | 对称 | 非对称 |
|---|---:|---:|
| 权重 T1（16 个张量中位数，见 §5） | GK=1024: 16.1 dB | GK=1024: **17.3 dB** |
| Tier-2 GEMM（64 层中位数，见 §4b） | 17.58 dB | **18.79 dB** |
| **PPL vs w8a8（完整 split, GK=1024）** | **+9.03%** | **+3.56%** |

参照物：非对称在 GK=1024 上买到的，比对称缩到 GK=128（8 倍组数）还多——
而按 P0 的代价表，GK 从 1024 缩到 256 就要付 2.4–4.1× 的 kernel 时间，128 更不可能。
零点的 kernel 代价则小得多——数学上：

```
Σ_{k∈g} A_q·(W_q − wz)  =  Σ_{k∈g} A_q·W_q  −  wz[n,g] · Σ_{k∈g} A_q[m,k]
```

只多一个**每组的激活行和** `AS[m,g]`，而这个量由本来就要写两个 int4 平面的 per-token
量化 kernel 顺手产出；AIV 侧多一个每组的秩一修正。它确实落在 P0 §2.5 定位的
「AIV 每组固定指令发射」瓶颈上，**不是免费的**，但比把组数翻 4 倍便宜得多。

**这不是路线图冻结的方案**，所以 harness 里是 opt-in（`--asym` /
`build_configs(include_asym=True)`），默认跑的仍是冻结的五组。数学正确性由自检 T4
的非对称用例覆盖（对 CPU int64 参考，相对误差 7.9e-8）。**建议 P2 把它作为一个正式
候选评估，而不是等到 P3 再返工。**

## 4b. 逐输入通道缩放（AWQ / SmoothQuant 方向）——**探针结论：只值 0.3–0.5 dB**

既然瓶颈在权重侧，一个自然的候选是 AWQ 式的 `W' = W·diag(s)`、`X' = X·diag(1/s)`
（`X'W'^T = XW^T` 恒等）。它在推理时**免费**——s 折进前一个 norm 的权重或前一个
Linear 的输出通道，kernel 一行不用改——所以值得在动手实现前先量一量。

`run_awq_probe.py`，全 64 层 × 7 个 Linear，两个相反方向：

| | s 的形式 | 效果 |
|---|---|---|
| `awq` | `mean\|X_j\|^α` | W 更难、A 更容易（AWQ / SmoothQuant 的方向） |
| `wflat` | `rms(W[:,j])^-β` | W 更容易、A 更难（我们的误差预算想要的方向） |

Tier-2（GEMM 输出 SNR）中位数，全 64 层，dB：

| 变体 | base | awq α=.25 | awq α=.5 | wflat β=.5 | wflat β=1 | mix(α=.25,β=.5) |
|---|---:|---:|---:|---:|---:|---:|
| weight-only（A 留 bf16，即 AWQ 自己的目标） | 17.66 | +0.05 | **−1.43** | +0.09 | +0.07 | **+0.23** |
| 完整 W4A8-mg 对称 | 17.58 | +0.08 | −1.36 | +0.09 | +0.08 | **+0.29** |
| 完整 W4A8-mg 非对称 | 18.79 | +0.21 | −0.85 | +0.07 | +0.07 | **+0.46** |

**连 AWQ 自己的做法（逐 Linear 网格搜索 α，取输出误差最小的那个）也只有
+0.25 / +0.30 / +0.47 dB 的中位增益**（均值 +0.61 / +0.66 / +0.79，被少数早期层
的大增益拉高，最大 +9.5 dB 出现在 L0/L1）。**60 多个层里它什么也没做。**

原因由结构诊断直接给出——逐输入通道离散度（max/median）的全模型中位数：

| | 激活 | 权重 |
|---|---:|---:|
| q/k/v_proj | 26.9× | **1.60 / 1.77 / 1.15×** |
| o_proj | 10.4× | 1.49× |
| gate/up_proj | 14.0× | 1.44 / 1.04× |
| down_proj | 22.5× | 1.34× |

**激活是强通道结构化的（10–27×），权重几乎是平的（1.04–1.77×）。** 逐通道缩放只能
搬运通道之间的难度；而 int4 权重的难度是**行内/组内的散布**，不是通道模式，所以
两个方向都无从下手。（顺带解释了为什么 `wflat` 能把权重 Tier-1 抬高 +0.17 dB 却对
输出 SNR 无效：它拉平了列范数，代价是恶化了大激活通道上的误差，正好抵消。）

### 但这个结论正面地指向 GPTQ

**误差是无结构散布**这件事恰恰是 GPTQ 的适用条件：GPTQ 逐列量化并把误差**补偿到尚未
量化的权重上**，处理的正是无结构误差；AWQ 处理的是通道级显著性，而这个模型在
GK=1024 上没有可利用的通道结构。所以探针不只是说「AWQ 不行」，它同时说明
**GPTQ 是对这类误差形状正确的工具**。

### 还差多少

完整 split 上的账（§3.2）：

| 杠杆 | Tier-2 | ΔPPL vs w8a8 |
|---|---:|---:|
| RTN 对称 GK=1024（起点） | 17.58 dB | +9.03% |
| **+ 权重零点** | 18.79 dB（+1.21） | **+3.56%** |
| + 逐通道缩放（本节，最优情形） | +0.3～0.5 dB | 按上面的斜率约值 **1.4～2.3 个百分点** |
| 门槛 | — | **≤2.00%** |

用这两个已测点粗校准（+1.21 dB Tier-2 ↔ 5.47 个 PPL 百分点，约 **4.5 点/dB**），
从 +3.56% 走到 ≤2% 只需要再 **~0.35 dB**。

**这个换算是两点线性外推，在接近门槛处必然失真**（ΔPPL→0 时需要的 dB →∞），所以
不要当成保证。但方向是清楚的：**缺口已经从「需要 2 dB，五五开」变成「需要零点几 dB」**，
GPTQ 在 4bit 上常见的 1–3 dB 输出误差改善**大概率够用**。

值得注意的是：0.3–0.5 dB 的逐通道缩放在缺口是 9 个百分点时可以忽略，在缺口只剩
1.56 个百分点时**已经不可忽略**。所以本节的结论要修正为——**AWQ 不能当主力杠杆，
但可以作为 GPTQ 之后的补齐手段重新考虑**（它推理时免费，只是校准麻烦）。

## 5. 交叉验证：低 SNR 不是 harness 的 bug

int4 权重 SNR 只有 13–18 dB，数字低到需要单独证伪「量化器写错了」：

| | 对称 pc | 对称 g1024 | 对称 g256 | 对称 g128 | 非对称 g128 |
|---|---:|---:|---:|---:|---:|
| 16 个张量的中位数（L0/1/31/63 × 4 投影） | 13.8 | 16.1 | 17.5 | 18.3 | **19.7** |

- 对称 int4 @ g128 = **18.3 dB**、非对称 = **19.7 dB**，正是 4-bit 均匀量化在
  近高斯分布上的理论水平（≈20 dB），**与文献一致**；
- 自检 T2 独立验过高斯输入下 int4 的 SNR 与理论值吻合（gk2048 16.6 dB vs 理论 15.9）；
- 非对称那一列走的是**另一份独立实现**（AWQ/GPTQ 式 min-max + zero point），
  与本 harness 的对称路径互为旁证。

结论：**13–18 dB 就是 4 bit 的本征代价**，不是 bug。RTN 在这个位宽上没有余量。

    --out fakequant_lab/results/gksweep_w8.json
python -m fakequant_lab.run_ppl --gk 1024 --windows 0 --asym \

## 7. 给 P2 的建议

1. **把非对称权重设为默认起点**（§4）。它是 P1 找到的最有价值的一件事：一步把缺口
   从 9.03 砍到 3.56 个百分点，而 kernel 代价只是每组多一个激活行和——远低于缩小 GK。
   这需要 P3 配合（per-token 量化 kernel 多吐一个 `AS[m,g]`），**现在就该定下来，
   不要等到 P3 返工**。
2. **跳过 RTN 对称，直接上 GPTQ**（路线图 §6 阶梯第 2 级），`group_size = GK`。
   剩下的缺口是 **1.56 个百分点 ≈ 0.35 dB Tier-2**（§4b 末，两点外推，接近门槛处会
   失真）。GPTQ 在 4bit 上常见 1–3 dB，**大概率够用**。
3. **不要花机时细化 GK**（§3.2c）：1024→128 组数 8 倍只赚回约 1/3 的缺口，而按 P0
   的代价表 GK=256 就要 2.4–4.1× kernel 时间。GK 曲线等 GPTQ 之后再确认一次即可。
4. **AWQ 不做主力，但别彻底扔掉**（§4b）：逐通道缩放两个方向都只值 0.3–0.5 dB，
   因为 QwQ-32B 的 int4 权重难度不是通道结构化的（权重逐通道离散度只有 1.04–1.77×）。
   在缺口 9 个百分点时可以忽略，在只剩 1.56 个百分点时**已经不可忽略**——留作 GPTQ
   之后的补齐手段。同一份数据正面支持 GPTQ：无结构散布正是它的适用条件。
5. **所有门禁数字必须在完整 test split 上取**（§3.2b）。小样本不是噪声大，而是
   **系统性高估退化近一倍**（前 8 个窗口的文本明显更容易）。
6. **门禁改用 PPL / 任务评测，以 W8A8 为参照系**；32/35 dB 的绝对判据作废（§3.4），
   Tier1/2 降级为诊断工具。KL(bf16‖cfg) 作为补充标量，`logit SNR` 不要用。
7. **注意 `down_proj`**：它的激活 crest factor 中位数 126，是全模型最难的一处，
   也是 mid-group 收益最大的一处（+8.5 dB）。
8. 若 GPTQ + 非对称仍过不了门槛，按路线图 §3 回退分支处理——注意回退目标
   `W4A8-pc` 实测 **+33.9%**，不是可用的回退点；真正的回退是 **W8A8-mg**
   （**−0.10%**，比 per-token W8A8 还略好，且 nitro 有现成实现）。
